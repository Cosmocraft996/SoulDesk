# 桌面宿主最小验证实施计划

> 执行要求：用户已明确授权在新会话实施。使用 `superpowers:executing-plans` 按任务顺序执行，复用本地现有工作区，不提交或推送；原交接会话仅整理计划，本执行会话实际推进。复选框只按实际结果勾选。

**目标：** 先证明现有 Tauri 能承载独立桌面组件及全高磨砂侧栏，再进入真实组件包的整合；两段本机隔离验证均已通过，实际证据、历史失败与兼容性缺口见 [09](09-桌面宿主最小验证记录.md)。

**架构：** 先增加隔离的桌面能力探针，使用时钟与卡片外观夹具验证 Windows 层级、焦点、磨砂及几何，不加载行情、不打开正常数据库。平台检查通过后，再用原组件包及消息桥完成真实组件整合；两段证据分开，不把静态夹具称为普通组件包验收。

**技术基线：** 沿用 Tauri 2.12.5、Rust、React/TypeScript、现有 Windows 绑定与已锁定依赖；不安装系统级工具，不预先替换宿主。

**设计依据：** [需求基线](01-需求文档-PRD.md)、[技术方案第 3 节](02-技术方案与Codex实施指南.md)、[证据与确认](03-参考项目源码审计与需求确认.md)。

## 全局约束

- 用户要求独立桌面组件为主，辅助面板为辅，管理窗口负责添加与设置。
- 宿主采用中性深色，组件配色独立多彩；面板为半透明磨砂，铺满可用高度，宽度按当前显示器可用工作区比例计算。
- 设计默认比例为 40%；草图的 20%～80% 是演示调节范围，不作为底层几何函数的硬编码限制。底层接受大于 0、且不超过 1 的有限比例，受最小可用宽度与工作区限制。
- 后台显示、恢复及调整层级不抢焦点；用户显式点击及输入应可用，不把整个组件永久设为不可激活。
- 不重启 Explorer，不修改正常数据库、系统代理、登录启动登记或全局环境；实际系统重建检查另行安排。
- 所有自动检查保留真实失败、未验证或不确定状态；API 调用返回不等于磨砂肉眼可见，不等于 Win+D 体验通过。
- 用户最新授权原文：“可以开始实施了, 但要交付到新的会话中执行”。该授权替代此前对第一阶段“不改代码”的限制，不必再次询问是否允许开始；实施须在新会话进行。本计划不包含完整组件库改版、正常数据库迁移、行情视图重写或打包发布。

## 重点故障边界

1. 负坐标副屏、缩放变化和很窄工作区：侧栏贴正确工作区右侧，宽高可达，不遮挡任务栏。
2. 极端比例、非有限数及最小宽度超过工作区：拒绝非法输入，合法输入有明确有效比例，不越界。
3. 桌面附着失败或旧句柄失效：保留诊断，不能转成普通置顶窗口后仍报告桌面模式通过。
4. 磨砂接口未应用、系统透明效果关闭或移动时异常：记录真实现象，不以设置调用成功冒充视觉效果通过。
5. 面板关闭、探针退出及异常：只清理本次窗口和资源，不影响已有 SoulDesk，也不遗留全局快捷键。

## 第一段：平台能力探针

### 任务一：工作区比例几何

**文件：** 新增 `src-tauri/src/desktop_geometry.rs`；在 `src-tauri/src/lib.rs` 登记模块。测试放在同一模块的 `#[cfg(test)]` 中。

**接口：**

- `WorkArea { left: i32, top: i32, width: u32, height: u32, scale_factor: f64 }`，坐标和宽高为物理单位。
- `PanelGeometry { left: i32, top: i32, width: u32, height: u32, requested_ratio: f64, effective_ratio: f64 }`。
- `panel_geometry(area: WorkArea, ratio: f64, min_width_logical: f64) -> Result<PanelGeometry, String>`；最小宽度按目标屏幕当前缩放换算，不读取系统或数据库。

- [x] 先增加行为测试：1920×1040、比例 0.4、缩放 1、最小逻辑宽 280，结果为 x=1152、y=0、宽 768、高 1040；左侧坐标为 -1920 时结果 x=-768。
- [x] 覆盖比例 0.2、缩放 1.5、最小逻辑宽 280，实际宽 420、有效比例 0.21875；工作区宽仅 240 时最大宽为 240。NaN、无穷、0、负比例和大于 1 的比例返回错误。
- [x] 执行 `node scripts/desktop.mjs test --locked desktop_geometry::tests`，确认新增断言在实现前失败，再实现最小纯计算并确认通过。
- [x] 记录舍入与边界策略：物理宽向上取整后限制在工作区内，右边缘严格等于工作区右边缘，高度严格等于工作区高度。

### 任务二：隔离的原生承载探针

**文件：** 新增 `src-tauri/src/desktop_probe.rs`、`src-tauri/src/bin/desktop-probe.rs`、`src/DesktopProbe.tsx`、`src/desktop-probe.css` 和 `src-tauri/capabilities/desktop-probe.json`；修改 `src/main.tsx`、`src-tauri/src/lib.rs`、`src-tauri/build.rs` 及实际生成的新命令权限。普通入口仍走原 App；不改变正常实例显隐或迁移数据库。

**接口与身份：**

- 库入口 `run_desktop_probe(report: std::path::PathBuf) -> Result<(), String>`，由独立二进制调用；报告路径必须是显式绝对路径。
- 三个固定窗口标签：`desktop-probe-clock`、`desktop-probe-card`、`desktop-probe-panel`；页面查询参数只选择探针外观，不能使正常应用获得探针后台权限。
- 窗口级命令 `desktop_probe_set_ratio(window, ratio: f64) -> Result<PanelGeometry, String>`，仅接收探针面板调用；其余组件页面无此权限。
- 报告结构至少包含运行标识、`phase=desktop-platform-probe`、系统及显示器信息、窗口身份、请求/有效比例、焦点前后值、原生错误与人工待确认项；不得设置 G0～G3 已通过。

- [x] 先测试报告路径拒绝相对路径、窗口身份拒绝伪造、无效比例不改变原几何；再实现最小解析和命令。
- [x] 使用现有依赖创建三个独立承载窗口；时钟和卡片是平台夹具，界面清楚标记探针，不装载正常组件实例或业务数据库。
- [x] 所有探针 WebView 使用本次报告目录下的独立数据目录，不复用正常应用的 WebView 配置、缓存或存储；退出不删除用户原有文件。
- [x] 桌面附着先依据拥有实现的源码核对候选方式，记录实际采用的原生步骤和失败结果；不凭桌面类名或“始终底层”推断 Win+D 已支持。
- [x] 优先尝试锁定 Tauri 公开 Acrylic；其失焦回退实色已实测，因此采用本机通过的窗口级 Accent Acrylic 适配。背景、文字分离，无新增特效依赖；未公开入口兼容性风险见 09。
- [x] 复用任务一的几何计算；面板贴工作区右侧且占满高度，调比例后保存到本次探针配置，重建时重新按当前工作区计算；只在探针报告目录下存储，不写正常偏好。
- [x] 验证程序退出只处理自己创建的窗口、监听和快捷键；附着失败明确报告，不静默用浮窗替代。
- [x] 前端类型/构建、全目标 Rust 编译/完整测试及格式检查通过，最终完整 Rust 87 项；实际命令及输出见 09。
