# 桌面组件 — 产品需求与验收基线

> 版本：v1.5｜修订日期：2026-11-14｜状态：0.4.0本机安装验收完成；0.5.0面板与更新改造见12  
> 用户已确认“独立组件直接摆在桌面上”为主，快捷键和侧边组件面板为辅，管理窗口负责添加与设置。本版替代 v1.1 的窗口式工作台主路径，不代表源码已完成纠偏。技术方案见 [02-技术方案与Codex实施指南.md](02-技术方案与Codex实施指南.md)，证据与确认过程见 [03-参考项目源码审计与需求确认.md](03-参考项目源码审计与需求确认.md)。

## 1. 产品目标与决策边界

产品是 Windows 首发的通用桌面组件宿主。用户日常直接查看和操作摆放在桌面上的独立组件。行情和价格警报是第一个需要完整交付的业务组件，同时必须证明普通组件能够独立导入，不能把产品收缩为仅支持行情的专用软件。

主要使用方式：

- 独立组件直接摆放在桌面上，管理窗口用于添加和设置；关闭管理窗口不影响桌面组件及后台规则。
- 快捷键和侧边组件面板作为补充入口，同时保留；面板不取代独立桌面组件的主路径。
- 后台启动、重连、数据刷新和警报均不抢焦点；建议启动时恢复上次可见的桌面组件，辅助面板及管理界面保持关闭。本次正式实施采用此恢复规则。
- 后续由 Codex 创建普通组件包，经管理界面导入并添加到桌面；新增特殊后台协议或系统能力时允许升级主程序。
- 电脑开机、用户登录且程序运行时提供本地监控；关机、休眠、离线期间不承诺代监控或还原未观测行情。

用户负责产品目标、首版范围、主要交互和重要成本取舍。Codex 负责专业资料核实、技术选型、规则细化、实现及验证；仅在宏观需求冲突或授权边界出现时再向用户确认。

专业默认规则在本版明确记录，由实现和测试验证。技术栈推荐不作为用户必须选择的题目，也不因写入文档就视为已经验证。

### 1.1 已确认边界与待细化内容

- 已确认：独立桌面组件为主，快捷键和侧边组件面板为辅，管理窗口负责添加与设置。参考体验为 Kepo 与 widget-js/widgets，不扩大为复制两者全部功能。
- 已确认的配色方向：宿主、辅助面板和管理界面采用 Codex 式或参考图的中性深色；组件自身可以丰富多彩，允许独立的纯色、渐变及品牌配色，保证文字可读性和状态语义，不强制继承宿主灰色。
- 已确认的侧边面板要求：半透明磨砂背景，高度占满；宽度可按屏幕比例调整，背景遮罩也可设置，两者均保存为面板偏好。设计按当前显示器可用工作区铺满高度、避开任务栏；默认值和可调边界由 Codex 按可用尺寸细化，不作为用户指定值。
- 已认可的草图方向：桌面独立摆放、紧凑行情、按需打开规则与历史，以及深色宿主和独立多彩组件。草图中的示例值和设计调节项不自动成为新业务或主题编辑器需求。
- 正式交互约定：默认组件位于普通应用下方，Win+D 时保留；置顶由用户选择；快捷键开关辅助面板；同一实例只占一个主展示位置；关闭组件仅隐藏视图。完整建议、恢复规则及待验证边界见技术方案第 3 节，按本次授权实施，正式集成与设备证据见11。
- 系统窗口或网页视图仍可作为技术载体，但普通应用窗口、取消标题栏或已有浮窗本身不能作为桌面组件体验完成的依据。

## 2. 首版范围

### 2.1 首个可用版本必须同时具备

1. 独立桌面组件、托盘、快捷键和侧边组件面板，以及负责添加与设置的管理界面。
2. 普通组件包的导入、配置、多实例、停用、升级失败保护；至少一个非行情外部组件成功导入。
3. 币安 USDT 永续自选行情、最新成交价与标记价格、本地到价警报和历史。
4. 共享后台、数据时效识别、断网/休眠恢复、配置保存、诊断和安装升级保护。

行情列表中的多个标的不等于多个网页视图。一个行情组件可显示多个标的，不要求为每个标的创建独立组件。添加组件的目标路径为直接摆放到桌面，无需先放进工作台再移到浮窗。

### 2.2 后续扩展

| 优先级 | 内容 | 进入条件 |
|---|---|---|
| P1 | RSS、简单 HTTP 服务器监控 | 首版稳定后，用于验证新的数据服务适配器 |
| P1 | 迷你走势图、按需 K 线图 | 行情与警报事件路径稳定后 |
| P1 | 更完整的组件开发模板、预览和打包流程 | 首版已经包含最小模板与独立导入验证 |
| P1 | 规则导入导出、涨跌幅/短时波动提醒 | 到价警报与恢复语义验证后 |
| P1 | 更复杂的全屏、虚拟桌面组合优化 | 基础桌面层级、Win+D 及恢复行为已定义并通过实机验证后扩展 |
| P2 | 翻译、汇率、便签、多工作区、更多市场 | 有明确使用需要时再实施 |

P0 表示首个可用版本的必要条件；P1/P2 不因出现在候选清单就自动进入首版。

### 2.3 本期不包含

公开组件商城、云账户、多用户、分享审核、通用脚本后台、复杂恶意代码沙箱、可视化规则引擎、内置大型 AI 编程代理、云端代监控、自动交易和钱包。

公开行情无需币安账户或 API Key。普通本地组件按用户信任的代码处理；宿主仍需限制资源路径和可调用能力。

### 3.3 币安行情

日常行情以桌面组件展示为主；用户已认可紧凑行情草图方向，规则编辑与历史查询按需进入。实际尺寸、排版和状态展示由 Codex 按组件契约细化；现有多页签管理页面不直接作为完成标准，不因此自动增加单币组件或图表业务。

| ID | 优先级 | 需求 |
|---|---|---|
| MARKET-01 | P0 | 动态发现实际支持、处于可用状态的 USDT 普通永续和 TradFi 永续；不硬编码候选标的永久存在 |
| MARKET-02 | P0 | 支持搜索、添加、删除和排序自选；至少验证 20 个不同的有效合约 |
| MARKET-03 | P0 | 最新成交价 Last 与标记价格 Mark 分别展示、订阅和用于警报；显示来源、时间及状态 |
| MARKET-04 | P0 | 后台集中订阅并共享数据；重复打开同币种组件不增加等价行情连接；有效规则保留所需订阅 |
| MARKET-05 | P0 | 分别识别连接健康、报价时效和交易状态；过期报价不产生新警报；没有新成交不直接等同于网络断线 |
| MARKET-06 | P0 | 支持直连、手动 HTTP 与 SOCKS5 代理；可解析的系统代理按技术方案处理；REST 和 WebSocket 使用同一用户意图 |
| MARKET-07 | P0 | 明确 24 小时涨跌的价格口径；不能把 Last 的统计值标为 Mark 的涨跌 |
| MARKET-08 | P0 | TradFi 合约标明类型；区分标的市场休市、合约自身状态和数据失效，不能仅凭股票休市就判定永续合约停盘 |

BTC、ETH、SOL 及原讨论中的股票/ETF 类合约均为候选，以运行时目录为准。币安合约报价不等于股票、ETF 或指数的现货报价。

### 3.4 到价警报

| ID | 优先级 | 需求 |
|---|---|---|
| ALERT-01 | P0 | 每个合约可设置多条向上/向下到价规则，并明确交易所、合约和 Last/Mark |
| ALERT-02 | P0 | 到价包含相等：向上达到或超过阈值，向下达到或低于阈值；不用显示后的舍入值判断 |
| ALERT-03 | P0 | 支持单次、可重复、冷却、暂停、编辑和删除；持续停留在阈值同一侧不形成无限重复事件 |
| ALERT-04 | P0 | 冷却期内回落后再次到价，结束时仍满足条件则补一条；多个被抑制事件合并，不积压通知 |
| ALERT-05 | P0 | 恢复后用新鲜有效报价检查尚未处理的条件；可产生“恢复后到价”，不虚构离线期间的穿越时间 |
| ALERT-06 | P0 | 一次性已触发规则不因重连、重启或重开界面重复发送；保留触发历史 |
| ALERT-07 | P0 | 规则判断在后台；通知与声音独立开关；静音不暂停规则和历史记录 |
| ALERT-08 | P0 | 历史包含规则、市场、价格类型、阈值、观测价格、时间、触发原因及通知结果；提供测试提醒 |

专业默认行为：

| 场景 | 预期结果 |
|---|---|
| 价格 99 → 100，向上阈值 100 | 提醒一次 |
| 提醒后价格一直为 100 或更高 | 不按每笔报价或每个冷却周期自动重复 |
| 冷却期内 101 → 99 → 100，结束时仍不低于 100 | 冷却结束补一条，重新开始冷却 |
| 同样的冷却场景，结束时已低于 100 | 不补；等待后续重新到价 |
| 冷却结束时离线、报价失效或还没有新的有效观测 | 不用旧价补发；后续结合新价和已保存状态复核 |
| 未触发规则断网前为 99，恢复第一笔有效价格为 101 | 提醒一次“恢复后到价”，不声称观察到了离线穿越 |
| 已处理的规则恢复时仍在阈值同一侧 | 不因恢复本身重播同一事件 |
| 新建/重新开启规则时价格已满足条件 | 保存前明确提示，启用后按有效价格提醒一次 |
| 编辑阈值、方向或价格类型 | 作为新规则版本重新检查；只改名称等描述不重新武装 |

以上保留用户已确认的到价和冷却补提醒要求；恢复、创建和编辑等细节是 Codex 依据专业资料及本地边界制定的默认方案。AICoin、TradingView 的公开说明用于界定语义，不代表本项目复制其未公开实现。依据与完整状态规则见技术方案。

### 3.6 2026-11-14确认的面板与发行行为

- 滑入、滑出分别可调，0～1000毫秒，默认各250毫秒；0表示立即显隐。
- 三种入口为桌面空白主键双击、可配置快捷键、鼠标移入吸边入口。双击默认开启且可关闭，图标、任务栏、组件及其他应用区域不触发。
- 双击与快捷键打开后保持展开，再次触发收起；鼠标悬停打开的面板在移出后立即开始收起，无等待延迟。输入、拖动、缩放、菜单及所属详情操作期间暂缓。
- 移除面板品牌标题、组件外层文字标题和常驻底部设置。常用入口为有中文提示的图标；宽度、遮罩、动效等按需打开设置。
- 桌面与面板使用同一组件外观和操作外壳。面板内自由拖动、调整尺寸；两种场景分别保存布局，同一实例继续只有一个主展示位置。
- 日常提交运行代码检查；版本标签或手动触发Windows自动打包，在当前公开仓库生成发布草稿，检查后再公开。更新私钥通过Secrets管理，同仓库发行使用内置GITHUB_TOKEN。

## 4. 验收基线

下列是项目验收目标，不是对交易所网络或 Windows 通知可见性的外部保证。模拟、核心逻辑检查和真实设备验收分别记录。

v1.1 的 G0～G3 报告及 04～07 实施记录继续保留，只证明其原范围内的能力。v1.2 起调整了 HOST、WIDGET 及 ACC 的桌面展示要求，旧编号通过不能直接视作新版要求通过；桌面形态已在0.4.0实施，正式集成和安装验收分别见11。

| ID | 覆盖范围 | 通过条件 |
|---|---|---|
| ACC-01 | HOST-01～08 | 按确认后的展示与交互设计验证独立桌面组件、辅助面板与管理界面分离；关闭管理界面或收起面板不影响桌面组件；验证单实例、托盘、快捷键冲突、显隐、退出和后台不抢焦点 |
| ACC-02 | HOST-09～10 | 按设计验证基础桌面层级、Win+D 与恢复；在可用设备上验证 100/125/150% 缩放和显示器移除，组件可找回。缺少设备的项目写“未验证”，不凭模拟宣称全平台通过 |
| ACC-03 | WIDGET-01～09 | 主程序构建不变，导入外部示例包并直接添加到桌面，创建两个实例分别配置、摆放并恢复；验证预置入口及桌面/面板复用；坏包和失败升级保留旧版 |
| ACC-04 | MARKET-01～08 | 20 个不同有效合约运行；同标的多视图复用订阅；Last/Mark 分别取证。真实 TradFi 可用时至少验证一个，未取得证据则单列未验证 |
| ACC-05 | ALERT-01～06 | 自动化覆盖本文件全部警报场景，并覆盖下行对称场景、重复/旧消息、重连、重启、规则修改和非法价格；预期事件数与记录完全一致 |
| ACC-06 | ALERT-07～08、REL-02、07 | 隐藏/销毁视图仍能经同一后台路径触发；通知、声音分别测试；模拟通知失败和崩溃边界，历史能说明实际结果 |
| ACC-07 | REL-01 | 10 次断网恢复、5 次休眠恢复；已确认网络和数据源可达的测试环境中，恢复后 60 秒内取得所需新行情；无旧连接残留和逻辑重复事件 |
| ACC-08 | REL-03～06 | 正常重启、保存失败、损坏数据、迁移失败及升级回退分别验证；已保存配置可恢复；备份通过 SQLite 完整性和版本检查 |
| ACC-09 | 整体稳定性 | 本轮连续30分钟运行：无未处理崩溃、无持续增加的重复订阅、无已知误触发；提交连接、通知、资源和故障统计。长期运行由用户后续日常使用自行验证，不作为本轮交付门槛 |

60 秒是受控测试的恢复超时上限；外部服务不可达时应显示失败并保留证据，不能伪装通过。性能先在本机建立预热后的 CPU、内存、视图数和后台任务数基线，再检查趋势；不提前编造内存或 CPU 实测数字。

2026-11-13用户明确调整：本轮持续运行验收由24小时缩短为30分钟，长期运行后续自行验证。保留原长期报告的真实未完成状态，不把30分钟结果称为24小时通过。

Windows 10/11 首发范围需分别取得适用证据。目前仅有本机部分核心检查，不代表两种系统全部验收完成。

## 5. 实施顺序

用户已在完成08/09隔离最小验证后，明确要求创建新实施会话并继续，授权正式程序改造、正常数据的安全兼容迁移实现、管理/面板分离和紧凑行情。本次直接实施正常应用，并以非空隔离副本验证迁移；真实安装或迁移正常用户库前提供清晰候选和备份边界，不自动安装、提交或发布。进度与结果见 [11-正式桌面组件实施与验收.md](11-正式桌面组件实施与验收.md)。

| 阶段 | 目标 | 必须交付 |
|---|---|---|
| G0 技术与组件加载验证 | 在已有加载和后台证据上补证独立桌面组件宿主能力 | 按确认设计实测桌面层级、Win+D、展示恢复、外部包与后台独立性；桌面专项待验证 |
| G1 通用桌面组件基础 | 完成独立组件布局、辅助面板、管理界面分离及可靠包管理 | 直接添加到桌面、布局恢复、最小模板、多实例和失败升级保护；新形态待实现 |
| G2 首个完整业务 | 行情、到价警报、恢复、历史与数据保护 | 真实数据组件、自动化规则检查、代理及恢复记录 |
| G3 首版验收 | 形成可日常使用的安装版本 | ACC-01～09 结果、已知限制、安装/备份说明及发布产物 |
| G4 按需扩展 | RSS、监控和更完整的组件开发工作流 | 每次只增加当前确需的能力，验证旧组件兼容性 |

G0/G1 已有独立组件包证据可复用；新形态必须补齐桌面展示验证。行情后台与规则的原有证据按受影响范围复用，不因纠偏无差别重做，也不替代新视图的验证。详细依赖、验证门槛、技术选择和产物格式以技术方案为准。
