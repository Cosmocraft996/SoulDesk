# 桌面组件 — 产品需求与验收基线

> 版本：v1.6｜修订日期：2026-11-19｜状态：0.5.2源码含57项WidgetJS本地移植；正常安装验收记录对应0.4.0
>
> 用户已确认“独立组件直接摆在桌面上”为主，快捷键和侧边组件面板为辅，管理窗口负责添加与设置。本版替代 v1.1 的窗口式工作台主路径，不代表源码已完成纠偏。技术方案见 [02-技术方案与Codex实施指南.md](02-技术方案与Codex实施指南.md)，证据与确认过程见 [03-参考项目源码审计与需求确认.md](03-参考项目源码审计与需求确认.md)。

## 1. 产品目标与决策边界

当前以宿主运行时、固定能力网关和独立组件包为边界。新安装从官方广场下载或导入本地 ZIP，已登记组件继续按原 ID 和实例数据运行。广场维护迁入的组件源码及公开目录，历史移植范围与人工验收记录见 13 和 20。

产品是 Windows 首发的通用桌面组件宿主。用户日常直接查看和操作摆放在桌面上的独立组件。行情和价格警报是第一个需要完整交付的业务组件，同时必须证明普通组件能够独立导入，不能把产品收缩为仅支持行情的专用软件。

主要使用方式：

- 独立组件直接摆放在桌面上，管理窗口用于添加和设置；关闭管理窗口不影响桌面组件及后台规则。
- 快捷键和侧边组件面板作为补充入口，同时保留；面板不取代独立桌面组件的主路径。
- 后台启动、重连、数据刷新和警报均不抢焦点；建议启动时恢复上次可见的桌面组件，辅助面板及管理界面保持关闭。本次正式实施采用此恢复规则。
- 后续由 Codex 创建普通组件包，经管理界面导入并添加到侧边面板，再按需移到桌面；新增特殊后台协议或系统能力时允许升级主程序。
- 电脑开机、用户登录且程序运行时提供本地监控；关机、休眠、离线期间不承诺代监控或还原未观测行情。

用户负责产品目标、首版范围、主要交互和重要成本取舍。Codex 负责专业资料核实、技术选型、规则细化、实现及验证；仅在宏观需求冲突或授权边界出现时再向用户确认。

专业默认规则在本版明确记录，由实现和测试验证。技术栈推荐不作为用户必须选择的题目，也不因写入文档就视为已经验证。

### 1.1 已确认边界与待细化内容

- 已确认：独立桌面组件为主，快捷键和侧边组件面板为辅，管理窗口负责添加与设置。参考体验为 Kepo 与 widget-js/widgets，不扩大为复制两者全部功能。
- 管理窗口、辅助面板和桌面组件的宿主外观使用同一主题。在应用设置中可选择墨蓝、松烟、燕麦和雾紫，默认墨蓝，切换后即时应用并跨重启保留。组件内部继续使用各自的配色。
- 桌面和侧边面板内的小组件默认内容铺满，去掉常驻外框和顶部留白；鼠标移入或键盘聚焦时浮出宿主工具栏。即使打开了“更多功能”，鼠标移出组件也会一并收起菜单和工具栏。宿主衬底由管理窗口的全局开关控制，默认关闭，开启时照片和大头贴仍保留透明轮廓。
- 已确认的侧边面板要求：半透明磨砂背景，高度占满。拖动面板朝屏幕内的边沿调整宽度，松开后保存为屏幕宽度比例。背景遮罩可设置，默认 50%。面板铺满当前显示器可用工作区高度并避开任务栏。
- 已认可的草图方向：桌面独立摆放、紧凑行情、按需打开规则与历史，以及深色宿主和独立多彩组件。草图中的示例值和设计调节项不自动成为新业务或主题编辑器需求。
- 正式交互约定：默认组件位于普通应用下方，Win+D 时保留；置顶由用户选择；快捷键开关辅助面板；同一实例只占一个主展示位置。眼睛按钮仅隐藏视图，垃圾桶按钮需二次确认后删除实例。面板组件通过工具栏的带箭头文件夹移动分组。窄组件将移入/放回、置顶及隐藏收入“更多功能”，该菜单也用于行情专用功能。完整建议、恢复规则及待验证边界见技术方案第 3 节，正式集成与设备证据见11、12。
- 系统窗口或网页视图仍可作为技术载体，但普通应用窗口、取消标题栏或已有浮窗本身不能作为桌面组件体验完成的依据。

## 2. 首版范围

### 2.1 首个可用版本必须同时具备

1. 独立桌面组件、托盘、快捷键和侧边组件面板，以及负责添加与设置的管理界面。
2. 普通组件包的导入、配置、多实例、停用、升级失败保护；至少一个非行情外部组件成功导入。
3. 币安 USDT 永续自选行情、最新成交价与标记价格、本地到价警报和历史。
4. 共享后台、数据时效识别、断网/休眠恢复、配置保存、诊断和安装升级保护。

行情列表中的多个标的不等于多个网页视图。一个行情组件可显示多个标的，不要求为每个标的创建独立组件。添加组件默认进入侧边面板当前分组，用户可从标题栏放到桌面。新增、恢复或移入组件时保持面板当前显隐、层级和分组。

### 2.2 后续扩展

| 优先级 | 内容 | 进入条件 |
|---|---|---|
| P1 | RSS、简单 HTTP 服务器监控 | 首版稳定后，用于验证新的数据服务适配器 |
| P1 | 迷你走势图、按需 K 线图 | 行情与警报事件路径稳定后 |
| P1 | 更完整的组件开发模板、预览和打包流程 | 首版已经包含最小模板与独立导入验证 |
| P1 | 规则导入导出、涨跌幅/短时波动提醒 | 到价警报与恢复语义验证后 |
| P1 | 更复杂的全屏、虚拟桌面组合优化 | 基础桌面层级、Win+D 及恢复行为已定义并通过实机验证后扩展 |
| P2 | 翻译、汇率、便签、多工作区、更多市场 | 有明确使用需要时再实施 |

P0 表示首个可用版本的必要条件；P1/P2 不因出现在候选清单就自动进入首版。

### 2.3 本期不包含

公开组件商城、云账户、多用户、分享审核、通用脚本后台、复杂恶意代码沙箱、可视化规则引擎、内置大型 AI 编程代理、云端代监控、自动交易和钱包。

公开行情无需币安账户或 API Key。普通本地组件按用户信任的代码处理；宿主仍需限制资源路径和可调用能力。

## 3. 功能需求

### 3.1 桌面宿主

| ID | 优先级 | 需求 |
|---|---|---|
| HOST-01 | P0 | 单实例；托盘可管理组件展示、打开管理界面和退出；可选择登录后启动，默认不强制开启 |
| HOST-02 | P0 | 全局快捷键可在设置中直接录入组合键、保存或关闭。新键位须含至少一个修饰键和一个主键，冲突时保留旧键并提示。默认仅切换辅助面板，全局隐藏的例外见技术方案 |
| HOST-03 | P0 | 独立组件直接摆放在桌面上；快捷键和侧边组件面板为辅助；同一实例切换展示位置时保留配置，不复制后台任务 |
| HOST-04 | P0 | 点击或悬停侧边挂件滑入半透明磨砂面板。未锁定时移出面板或失焦 3 秒后收起，外部主键点击立即收起。锁定时点击外部置底，手动入口切换置顶和置底，直接解锁提回置顶。快捷键和桌面空白双击均可锁定并展开，或解锁并收起。锁定偏好跨重启保留。挂件可拖动跨屏，面板占满对应显示器的可用高度，停靠位置自动保存 |
| HOST-05 | P0 | 管理窗口关闭不影响独立桌面组件和后台；隐藏、收起、关闭组件视图均不停止有效警报；只有明确退出才停止程序 |
| HOST-06 | P0 | 以组件内容为主体；宿主提供可持久化的深色和浅色主题，各组件允许独立多彩配色；保证清晰数字、可读性和克制动画；配置与管理操作按需进入；启动、网络恢复、警报触发不抢焦点 |
| HOST-07 | P0 | 保存桌面布局、组件尺寸、位置、展示归属及实例配置；建议启动恢复上次可见的桌面组件，面板和管理界面默认关闭；隐藏、移除实例与删除警报明确区分 |
| HOST-08 | P0 | 默认提供桌面组件模式，建议普通应用可覆盖组件、显示桌面时保留；置顶由用户选择，不进入系统安全桌面；通知不激活管理窗口；行为须实测 |
| HOST-09 | P0 | 基础缩放和显示器变化后组件可找回；断开副屏、改变分辨率后校正到可用工作区，不能只剩不可见组件 |
| HOST-10 | P0 | 基础桌面层级、显示桌面（Win+D）及恢复行为在实现前形成明确预期并验证；不得推迟为后续优化或用普通浮窗通过代替 |

鼠标、快捷键与显示恢复的具体状态转换由技术方案统一定义，不再由不同组件各写一套。v1.3 补齐 Codex 推荐的交互细则供整体评审；系统能力的本机隔离最小验证已通过；0.4.0 正式集成单独记录于11，其他设备不因本机通过而补齐。

### 3.3 币安行情

日常行情以桌面组件展示为主；用户已认可紧凑行情草图方向，规则编辑与历史查询按需进入。实际尺寸、排版和状态展示由 Codex 按组件契约细化；现有多页签管理页面不直接作为完成标准，不因此自动增加单币组件或图表业务。

| ID | 优先级 | 需求 |
|---|---|---|
| MARKET-01 | P0 | 动态发现实际支持、处于可用状态的 USDT 普通永续和 TradFi 永续；不硬编码候选标的永久存在 |
| MARKET-02 | P0 | 支持搜索、添加、删除和排序自选；至少验证 20 个不同的有效合约 |
| MARKET-03 | P0 | 最新成交价 Last 与标记价格 Mark 分别展示、订阅和用于警报；显示来源、时间及状态 |
| MARKET-04 | P0 | 后台集中订阅并共享数据；重复打开同币种组件不增加等价行情连接；有效规则保留所需订阅 |
| MARKET-05 | P0 | 分别识别连接健康、报价时效和交易状态；过期报价不产生新警报；没有新成交不直接等同于网络断线 |
| MARKET-06 | P0 | 支持直连、手动 HTTP 与 SOCKS5 代理；可解析的系统代理按技术方案处理；REST 和 WebSocket 使用同一用户意图 |
| MARKET-07 | P0 | 明确 24 小时涨跌的价格口径；不能把 Last 的统计值标为 Mark 的涨跌 |
| MARKET-08 | P0 | TradFi 合约标明类型；区分标的市场休市、合约自身状态和数据失效，不能仅凭股票休市就判定永续合约停盘 |

BTC、ETH、SOL 及原讨论中的股票/ETF 类合约均为候选，以运行时目录为准。币安合约报价不等于股票、ETF 或指数的现货报价。

### 3.4 到价警报

| ID | 优先级 | 需求 |
|---|---|---|
| ALERT-01 | P0 | 每个合约可设置多条向上/向下到价规则，并明确交易所、合约和 Last/Mark |
| ALERT-02 | P0 | 到价包含相等：向上达到或超过阈值，向下达到或低于阈值；不用显示后的舍入值判断 |
| ALERT-03 | P0 | 支持单次、可重复、冷却、暂停、编辑和删除；持续停留在阈值同一侧不形成无限重复事件 |
| ALERT-04 | P0 | 冷却期内回落后再次到价，结束时仍满足条件则补一条；多个被抑制事件合并，不积压通知 |
| ALERT-05 | P0 | 恢复后用新鲜有效报价检查尚未处理的条件；可产生“恢复后到价”，不虚构离线期间的穿越时间 |
| ALERT-06 | P0 | 一次性已触发规则不因重连、重启或重开界面重复发送；保留触发历史 |
| ALERT-07 | P0 | 规则由后台判断；灵动行情铃声由宿主统一开关，支持分别选择和试听上涨、下跌铃声；静音不暂停规则和历史记录 |
| ALERT-08 | P0 | 历史包含规则、市场、价格类型、阈值、观测价格、时间、触发原因及通知结果；提供测试提醒 |

专业默认行为：

| 场景 | 预期结果 |
|---|---|
| 价格 99 → 100，向上阈值 100 | 提醒一次 |
| 提醒后价格一直为 100 或更高 | 不按每笔报价或每个冷却周期自动重复 |
| 冷却期内 101 → 99 → 100，结束时仍不低于 100 | 冷却结束补一条，重新开始冷却 |
| 同样的冷却场景，结束时已低于 100 | 不补；等待后续重新到价 |
| 冷却结束时离线、报价失效或还没有新的有效观测 | 不用旧价补发；后续结合新价和已保存状态复核 |
| 未触发规则断网前为 99，恢复第一笔有效价格为 101 | 提醒一次“恢复后到价”，不声称观察到了离线穿越 |
| 已处理的规则恢复时仍在阈值同一侧 | 不因恢复本身重播同一事件 |
| 新建/重新开启规则时价格已满足条件 | 保存前明确提示，启用后按有效价格提醒一次 |
| 编辑阈值、方向或价格类型 | 作为新规则版本重新检查；只改名称等描述不重新武装 |

以上保留用户已确认的到价和冷却补提醒要求；恢复、创建和编辑等细节是 Codex 依据专业资料及本地边界制定的默认方案。AICoin、TradingView 的公开说明用于界定语义，不代表本项目复制其未公开实现。依据与完整状态规则见技术方案。

水平警报也支持向上及向下穿越。启用、重启或重连时首笔有效报价只建立基准，后续从指定方向触及或越过警报价时触发。可选单次或每次穿越。每条规则可以选择 Windows 或灵动通知，点击打开事件对应的 K 线。已有到价规则及通知方式继续沿用。灵动行情通知按同市场、同交易对覆盖，不同交易对叠加，关闭时停止该条铃声。

### 3.5 数据、恢复和交付

| ID | 优先级 | 需求 |
|---|---|---|
| REL-01 | P0 | 断网、代理切换、休眠唤醒后自动恢复所需订阅；恢复过程中显式显示连接与数据状态 |
| REL-02 | P0 | 视图隐藏、卸载或渲染异常不停止后台规则；后台失败不能只在控制台静默记录 |
| REL-03 | P0 | 配置、自选、组件及规则保存有明确成功/失败反馈；异常退出不把已保存数据恢复成默认值 |
| REL-04 | P0 | 提供本地诊断日志、导出和基本连接诊断；日志不含代理密码等敏感信息 |
| REL-05 | P0 | Windows 安装包提供「保留用户数据安装」和「完全覆盖安装」，默认保留数据。完全覆盖需二次确认，将当前用户的旧数据移到同级备份目录，新程序从空白数据启动。检测到 SoulDesk 正在运行时，用户确认后自动关闭，取消则返回安装方式选择。应用内更新默认保留数据。完成页可选立即启动新程序。通过系统单独卸载时默认保留数据，可明确选择删除 |
| REL-06 | P0 | 主程序升级前备份并检查数据版本；迁移失败保留原数据；配置导出不携带明文凭证 |
| REL-07 | P0 | 触发记录与规则状态一致保存；能区分规则已触发、通知发送失败和发送结果不确定 |
| REL-08 | P1 | 是否需要外部进程监督来实现崩溃自动重启，依据首版稳定性证据决定；不提前建设守护服务 |

### 3.6 2026-11-14确认的面板与发行行为

- 滑入、滑出分别可调，范围为 0～1000 毫秒，当前默认各 100 毫秒。0 表示立即显隐。

- 移除面板品牌标题、组件外层文字标题和常驻底部设置。常用入口为有中文提示的图标；遮罩、动效等按需打开设置；宽度按2026-11-17要求改为拖动面板左边沿调整。
- 桌面与面板使用同一组件外观和操作外壳。面板内自由拖动、调整尺寸；两种场景分别保存布局，同一实例继续只有一个主展示位置。
- 2026-11-17确认：桌面和面板组件在拖动及调整尺寸时自动对齐附近组件边缘及工作区／面板边界；缩放保留固定的左上角与组件最小尺寸，继续拖动可以脱离吸附。面板仅以当前分组可见组件为参照。吸附生效时双方对应边线突出显示并带动效，脱离或松手后淡出。
- 2026-11-17确认：面板顶部分组标签切换，只显示当前组，组内保留自由布局。每实例属于一个组，原组件归入固定的“未分组”；支持新建、改名、排序及组件菜单移动分组。删除分组时组件退回未分组，保留配置和内容；分组及归属持久保存。
- 2026-11-19确认：拖动侧边面板顶部标签可排序，松手后保存。“未分组”固定在首位。
- 2026-11-20确认：从侧边面板的组件拖动手柄拖到另一分组标签，松手后将组件移入该组。也可拖到“未分组”。移动后停留在当前组，宿主在目标组为组件安排位置。
- 2026-11-19确认：从桌面移入面板或移动到其他分组时，从目标组顶部向下找空位，同一高度先从左到右找，横向放不下再往下找。保留移入组件的尺寸及目标组已有组件的位置。

## 4. 验收基线

下列是项目验收目标，不是对交易所网络或 Windows 通知可见性的外部保证。模拟、核心逻辑检查和真实设备验收分别记录。

v1.1 的 G0～G3 报告及 04～07 实施记录继续保留，只证明其原范围内的能力。v1.2 起调整了 HOST、WIDGET 及 ACC 的桌面展示要求，旧编号通过不能直接视作新版要求通过；桌面形态已在0.4.0实施，正式集成和安装验收分别见11。

| ID | 覆盖范围 | 通过条件 |
|---|---|---|
| ACC-01 | HOST-01～08 | 按确认后的展示与交互设计验证独立桌面组件、辅助面板与管理界面分离；关闭管理界面或收起面板不影响桌面组件；验证单实例、托盘、快捷键冲突、显隐、退出和后台不抢焦点 |
| ACC-02 | HOST-09～10 | 按设计验证基础桌面层级、Win+D 与恢复；在可用设备上验证 100/125/150% 缩放和显示器移除，组件可找回。缺少设备的项目写“未验证”，不凭模拟宣称全平台通过 |
| ACC-03 | WIDGET-01～09 | 主程序构建不变，导入外部示例包并默认添加到面板当前分组，再移到桌面；创建两个实例分别配置、摆放并恢复；验证预置入口及桌面/面板复用；坏包和失败升级保留旧版 |
