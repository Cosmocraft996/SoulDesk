# 公开内容来源与图片权限

热点资讯、日历与大头贴分别声明实际读取的公开来源及外部图片权限。

| 组件 | 可读来源 | HTTPS图片 | 版本 |
| --- | --- | --- | --- |
| B站新番时间表、B站推荐 | 各自的 bangumi、bilibili-rcmd | 封面或图标 | 0.1.2 |
| 财联社电报 | cls-telegraph | 无外部图片需求 | 0.1.2 |
| 热榜 | bilibili、douyin、tou-tiao、weibo、zhihu | 榜单徽标 | 0.1.2 |
| 日历、大号日历 | `itime-calendar` | 无外部图片需求 | 0.1.2、0.2.3 |
| 大头贴 | 无 | 自填HTTPS图片地址 | 0.1.1 |

`content.source.<来源>`只允许调用该来源的`content.get`。宿主在命中缓存或联网前检查窗口、会话及权限，异步返回后再次检查会话。`images.https`只授予浏览器HTTPS图片加载许可，保留原图片域名范围。组件原静态资源、本地图片、打开链接、缓存、手动刷新和数据格式沿用现有实现。

旧`content.read`保留已开放的固定来源和HTTPS图片许可。8款金融组件在本批沿用旧声明，后续迁移见[19-架构审计收尾](19-架构审计收尾.md)。旧权限和细分项不可混用。新包须先更新宿主，再独立导入或在组件库显式升级。既有版本资源按各版本绑定的清单计算策略，正式升级流程保留实例和数据快照。
