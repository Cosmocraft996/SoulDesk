- Kepo 产品本体另核对官网；公开开发技能仓库单独审阅。没有取得完整 Kepo 桌面宿主源码。

## 3. 影响实施的主要发现

### 3.1 crypto-widget 的现货警报链路不能直接变成合约警报

[常驻行情地址](https://github.com/MERSEI/crypto-widget/blob/a7f0c04368ddc2a29bd700a781a934564ff1b00b/src-tauri/src/market/binance_ws.rs#L12-L14)使用现货 stream.binance.com；[行情中心](https://github.com/MERSEI/crypto-widget/blob/a7f0c04368ddc2a29bd700a781a934564ff1b00b/src-tauri/src/market/hub.rs#L78-L93)把有效更新送入警报引擎。规则没有价格类型字段，使用 f64。仓库中的 [另一组合约模块](https://github.com/MERSEI/crypto-widget/blob/a7f0c04368ddc2a29bd700a781a934564ff1b00b/src-tauri/src/futures/binance.rs#L319-L342)处理签名账户与持仓接口，不是本文需要的公开合约 Last/Mark 警报服务。

可以借鉴 Rust 后台与界面分离、集中订阅和显示节流；市场身份、价格类型、精度和触发事件需要按本项目重新明确。

### 3.2 原警报实现的重连保护不覆盖价格到价规则

[重连处理](https://github.com/MERSEI/crypto-widget/blob/a7f0c04368ddc2a29bd700a781a934564ff1b00b/src-tauri/src/market/hub.rs#L127-L134)清空波动缓冲区并设置预热时间；[规则判断](https://github.com/MERSEI/crypto-widget/blob/a7f0c04368ddc2a29bd700a781a934564ff1b00b/src-tauri/src/alerts/engine.rs#L108-L146)只有 Spike 分支检查预热。已有价格规则的 armed 状态没有在该重连路径重置。

因此，断档前处于等待侧、恢复后首次价格已到另一侧时，沿用该代码仍可能通知，不能满足原讨论中“不把断档当连续穿越”的要求。此项属于源码确认的路径风险；本轮 Rust 隔离探针因缺少链接器未运行，不把它写成完整应用实测结果。

后续需求更新：用户要求参考专业预警方案，由 Codex 负责技术判断。此项保留为相对原讨论定义的差异；到价类规则恢复后的条件检查采用第 8 节约定，不再将所有恢复提醒都归为误报。

### 3.3 备用交易所价格也进入同一警报引擎

[备用市场](https://github.com/MERSEI/crypto-widget/blob/a7f0c04368ddc2a29bd700a781a934564ff1b00b/src-tauri/src/market/backup.rs#L22-L30)包括 OKX、Bybit 等；备用价格携带来源并进入共享行情路径，[警报调用](https://github.com/MERSEI/crypto-widget/blob/a7f0c04368ddc2a29bd700a781a934564ff1b00b/src-tauri/src/market/hub.rs#L58-L93)没有根据规则限定交易所。更换来源时清空波动缓冲区，并未同时解决价格规则跨市场比较的问题。

本项目若采用该结构，币安合约规则必须绑定具体市场和价格类型；显示回退行情与执行警报的资格需要分别处理。

### 3.4 rtugeek/stock 的共享订阅存在可复现的卸载问题

[多个监听被合并](https://github.com/rtugeek/stock/blob/0f5157961908bb3fdec71d443117783a3496571f/src/hooks/use-coin-tickers.ts#L181-L195)后，[卸载清理](https://github.com/rtugeek/stock/blob/0f5157961908bb3fdec71d443117783a3496571f/src/hooks/use-coin-tickers.ts#L203-L209)直接删除整个币种键。两个组件订阅同一币种时，卸载其中一个会影响另一个。

在本机用原始模块逻辑、框架替身与模拟 WebSocket 复现：A、B 均先收到 BTC 更新；卸载 A 后，B 收不到后续更新。这个实现不能直接作为工作台多个组件共享数据的中心。

### 3.5 DockHub 的安装流程不能保证失败时保留旧版

[安装逻辑](https://github.com/sametgurtuna/DockHub/blob/7e2e50729d929f7bd0a33ad56d4af2bc52f170f9/src/CustomDock/Widgets/Web/WebWidgetCatalog.cs#L212-L227)先删除旧目录，再复制和读取新版本。新文件复制或校验失败时，没有在该流程中看到恢复旧目录的机制。可参考它的包格式、声明和桥接，但不能直接继承其更新失败行为。

另外，[README](https://github.com/sametgurtuna/DockHub/blob/7e2e50729d929f7bd0a33ad56d4af2bc52f170f9/README.md#L714-L716)明确表示暂未提供许可文件、作者保留全部权利。应保留为设计参考，当前不把源码列为可直接移植材料。

### 3.6 多个参考项目的“组件”实际上是构建时注册

Lumos 与 Themia 均有静态导入的组件注册表。它们能证明网格或浮窗模式存在，不能证明本项目要求的“导入一个新组件包，不重编译宿主”。Widget.js React 接口也依赖其自有宿主运行时。

应在工作台设计早期加入生产安装包的组件加载验证；不必一次实现完整插件平台。

### 3.7 参考窗口默认行为不完全符合用户要求

crypto-widget [默认强制置顶并按设置显示](https://github.com/MERSEI/crypto-widget/blob/a7f0c04368ddc2a29bd700a781a934564ff1b00b/src-tauri/src/lib.rs#L121-L130)，且其 [屏幕区域计算](https://github.com/MERSEI/crypto-widget/blob/a7f0c04368ddc2a29bd700a781a934564ff1b00b/src-tauri/src/window.rs#L20-L32)明确未排除任务栏。Demobar 的 AppBar 还可以改变系统可用工作区。这些均不能直接当作本项目默认策略。

原警报通知函数还会在 toast 开关关闭时直接返回，声音依附系统通知；如果继续采用“声音与系统通知分别开关”的参考要求，需要另行适配。

### 8.2 本项目的专业处理约定

以下是依据已确认目标和本地运行边界制定的实现约定，不是对 AICoin 内部实现的复刻声明，也不新增其他预警种类。

本节保留确认过程和依据；规则状态、接口及阶段验收的当前实施细则，以 02 的当前版本为准。

1. 到价提醒包含阈值本身，保留用户已确认的到价行为。单次触发、重复触发、通知与声音分别建模，避免把重复响铃当作新的警报事件。
2. 冷却期内再次到价的事件合并处理；冷却结束且有效价格仍满足条件时，按 R-06 补一条提醒，不堆积多条过时通知。
3. 网络中断、休眠及数据失效期间暂停行情条件判断，保留规则与已处理状态；不得使用过期报价产生新警报。
4. 恢复后，以对应交易所、合约及价格类型的新鲜有效报价检查仍启用且尚未处理的到价条件。条件成立可提醒一次，原因标为“恢复后到价”；不声称知道离线期间首次到价的时间或完整价格轨迹。
5. 已触发的单次规则不因重连或重启重新发送。重复规则结合持久化的触发状态、冷却及待补提醒去重，不能每次重连都重播同一事件。
6. 重连、连续行情中的再次到价、冷却补提醒分别记录原因并设置验证用例。最终行为必须经实现验证，当前仍属于设计约定。
