## 实施范围

- 单仓库 Tauri 2 / Rust / React / TypeScript / Vite 工程，pnpm 与 Cargo 锁文件。
- 核心进程拥有托盘、全局快捷键、统一显隐、侧边入口、浮窗和后台测试事件。
- ZIP 外部组件包通过自定义 `widget` 协议加载，不加入宿主静态注册表；工作台与浮窗共用实例配置与接口。
- SQLite 保存组件登记、实例配置、宿主偏好与测试事件。此阶段没有行情或真实警报规则。
- REST 与 WebSocket 共用直连、HTTP、SOCKS5 配置意图；显式取消连接和读取。

## 采用的工程约定

- 起步继续使用用户指定的当前工作区与 `main`，不因执行 Skill 创建新仓库、强制提交或更换工作区。执行记录放在本文，避免中断后重复实施。
- 项目启动脚本仅对子进程补充既有 Rust 目录，不写系统 PATH；构建依赖只在项目声明，只有 `esbuild` 的必要安装脚本得到允许。
- G0 拒绝替换已登记的不同组件包，保留旧包与配置；完整受限试加载、升级及回退属于 G1，不能以“拒绝升级”标记其完成。
- 初始通知插件在 Windows 上异步发送且忽略内部发送错误，因此历史记为 `unknown`。用户反馈未观察到提醒后，Windows 适配器改为直接等待同一 Tauri 维护的 WinRT 实现返回；`sent` 仅表示系统调用成功，仍不等于用户看到。声音在独立工作线程等待播放结束，避免退出截断。
- 实机探针只在显式 `--g0-smoke` 参数下启用，使用报告旁的独立验证数据目录；正常启动不创建测试实例或测试事件。
- 安装验收入口必须从普通、未继承其他应用 MSIX 身份的 PowerShell 运行。脚本在启动前查询包身份并保存独立上下文记录；不会尝试修改宿主包、系统 PATH 或默认运行时来规避该限制。
- Tauri 把注册的自定义协议也视为本地来源。宿主为顶层容器单独注入临时令牌，全部业务命令入口验证该令牌；组件只能使用会话桥，不直接获得宿主命令权限。安装版探针还检查直接调用被拒绝。

- [币安当前 Market 流接口](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/ws-streams/market)：真实连接探针采用 `/market/ws/btcusdt@markPrice@1s`；不把旧 `/ws` 路由继续作为新实施基线。
